# Phase 2 — CI / Build / Packaging Design

Aligned with [foundation/roadmap.md](../foundation/roadmap.md) Phase 2 and
[foundation/design.md](../foundation/design.md) BUILD & PACKAGING.

This document is the **normative technical contract** for Phase 2: three GitHub
Actions workflows, three composite actions, supporting config, and the file
inventory. It defines the **what** and the **why**; the ordered implementation
tasks are generated by the `writing-plans` skill in `tasks.md` (out of scope for
this document).

## SCOPE

### In scope

- GitHub Actions workflows: `review.yml`, `release.yml`, `publish.yml`.
- Composite actions: `setup-bun-project`, `junit-summary`, `package-electrobun`.
- `release-it` configuration (inline in `package.json`) with conventional
  changelog generation.
- Electrobun-driven macOS signing + notarization, gated by `ELECTROBUN_*` env
  vars with graceful unsigned fallback.
- Linux x64 + Linux arm64 + darwin-arm64 distribution.
- `.tar.gz` (Linux) and `.dmg` (macOS) artifacts uploaded to GitHub Releases
  with build-provenance attestations.
- Local mirror tasks under `mise run ci:*`.
- Single CI/CD guide at `assets/guides/CI_GUIDE.md` and a `CI / CD` section in
  `README.md`.

### Out of scope

- Windows builds (deferred to a later phase per `foundation/requirements.md`
  OUT OF SCOPE).
- Linux signing (no GPG keys provisioned; `.tar.gz` ships unsigned).
- App auto-update delivery (deferred to a later phase per
  `foundation/requirements.md` OUT OF SCOPE).
- DockerHub image publishing (app is not a server binary).
- Container Structure Tests (app is not a Docker image).
- Apple Developer Program enrollment (administrative; assumed to be done
  externally before signing is enabled).

## DESIGN DECISIONS

This section enumerates the patterns adopted, the patterns explicitly
rejected, and the rationale for each.

### Adopted patterns

| Pattern                                                        | Where                 | Rationale                                                                                  |
| -------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| Grouped lint chain with per-tool exit-code aggregation         | `review.yml` lint job | One job rather than N parallel jobs; faster, single artifact, single GitHub-summary table  |
| JUnit XML + `mikepenz/action-junit-report` for the test job    | `review.yml` test job | Native GitHub Checks integration, fail-on-failure semantics                                |
| Squash-and-merge enforcement at the workflow boundary          | `release.yml`         | Catches misconfigured branch protection; rejects merge commits and rebase-merge explicitly |
| SSH-agent + signed commits and signed tags                     | `release.yml`         | Consistent with the repo's signing posture; release-it inherits the agent automatically    |
| Two-step signing self-test (signed commit + signed tag)        | `release.yml`         | Pre-flight gate before release-it touches HEAD; fails fast on misconfig                    |
| Draft GitHub Release in release.yml, un-drafted by publish.yml | `release.yml`         | Ensures assets + attestations are validated before the release becomes public              |
| `workflow_run` chaining with `workflow_dispatch` recovery      | `publish.yml`         | Auto-runs after Release; manual recovery for failed publishes                              |
| `resolve_tag` job that gates on upstream Release success       | `publish.yml`         | Single source of truth for the release tag; prevents publish on cancelled/failed releases  |
| `fail-fast: false` matrix with single-writer `attach_release`  | `publish.yml`         | One leg failing doesn't block partial publish; only one job touches the release surface    |
| `actions/attest-build-provenance@v2` + `gh attestation verify` | `publish.yml`         | SLSA build-provenance for every artifact; verified twice (after upload, before un-draft)   |
| Composite `setup-bun-project` (mise mode + lockfile cache)     | All workflows         | Single touch-point for env setup; mise mode ensures ast-grep is available                  |
| Composite `junit-summary` (pure-bash JUnit→markdown)           | `review.yml`          | Zero external action dependency; works without internet pulls                              |

### Rejected patterns

| Pattern                                          | Why rejected                                                                                                                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hadolint in the lint chain                       | No Dockerfile in this repo                                                                                                                                                   |
| Container Structure Test (CST) job               | Not a Docker image; binary correctness is covered by `bun test`                                                                                                              |
| DockerHub preview image per PR                   | Not a server binary; PR reviewers can build locally with `bun run dev` or download the `build-smoke-linux-x64` artifact                                                      |
| Multi-platform OCI image push at release time    | Not a Docker distribution channel                                                                                                                                            |
| Bun `--target=...` cross-compile from one runner | Doesn't bundle the OS-native webview that Electrobun requires; native build per runner is correct                                                                            |
| `--platform=mac,linux` in a single matrix job    | macOS signing must run on `macos-latest`; Linux signing is out of scope (no GPG key); cleanest split is one runner per target                                                |
| QEMU emulation for `linux-arm64`                 | GitHub-hosted `ubuntu-24.04-arm` runners (GA 2025) are native, free for public repos, and far faster than QEMU                                                               |
| Hand-rolled `hdiutil` DMG creation               | Electrobun's `build.mac.createDmg: true` (default) creates the DMG itself, signs it as part of the codesign step, and notarizes the DMG; rolling our own duplicates the work |
| Standalone `entitlements.mac.plist` file         | Electrobun reads inline `build.mac.entitlements: Record<string, ...>` and writes the plist itself                                                                            |
| Standalone `.release-it.json`                    | Inlined under the `release-it` key in `package.json` per the user-confirmed style choice                                                                                     |
| Per-workflow guide files                         | Single consolidated `assets/guides/CI_GUIDE.md` chosen over 4 separate guides for maintainability and cross-workflow troubleshooting                                         |

## ARCHITECTURE

### Trigger graph

```
PR opened/synced ──► review.yml      (ubuntu-latest)
                     ─ lint
                     ─ test
                     ─ build (linux-x64 smoke)

PR squash-merged
push: main      ──► release.yml      (ubuntu-latest)
                     ─ validate squash-and-merge
                     ─ ssh-agent + signed commits/tags
                     ─ signing self-test
                     ─ bun run release:ci  (release-it)
                     ─ poll for draft release

                     │ workflow_run: completed
                     ▼
                     publish.yml
                     ─ resolve_tag      (ubuntu-latest)
                     ─ binaries  matrix:
                         • linux-x64    (ubuntu-latest)
                         • linux-arm64  (ubuntu-24.04-arm)
                         • darwin-arm64 (macos-latest)
                     ─ checksums      (ubuntu-latest)
                     ─ attach_release (ubuntu-latest)
                     ─ publish_release (gate + verify)
```

### Concurrency

| Workflow      | Group                                        | cancel-in-progress                            |
| ------------- | -------------------------------------------- | --------------------------------------------- |
| `review.yml`  | `app-${{ github.ref }}`                      | true                                          |
| `release.yml` | `app-release`                                | **false** — never cancel an in-flight release |
| `publish.yml` | `app-${{ github.ref_name \|\| inputs.tag }}` | true                                          |

### Build targets

| Target         | Runner             | Artifact                                                                                               | Notes                                                      |
| -------------- | ------------------ | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `linux-x64`    | `ubuntu-latest`    | `app-<ver>-linux-x64.tar.gz`                                                                           | —                                                          |
| `linux-arm64`  | `ubuntu-24.04-arm` | `app-<ver>-linux-arm64.tar.gz`                                                                         | Native ARM hosted runner (GA 2025)                         |
| `darwin-arm64` | `macos-latest`     | `app-<ver>-darwin-arm64.dmg` (signed) **or** `app-<ver>-darwin-arm64-unsigned.dmg` (unsigned fallback) | Electrobun handles sign + notarize + staple + DMG creation |

## SECRETS AND VARIABLES

Eight secrets, three variables. Single source of truth (this section).

| Kind   | Name                         | Workflow(s)      | Required     | Purpose                                                             |
| ------ | ---------------------------- | ---------------- | ------------ | ------------------------------------------------------------------- |
| secret | `GH_TOKEN`                   | Release, Publish | yes          | PAT bypassing branch protection; release-it + `gh release` calls    |
| secret | `RELEASE_SIGNING_SSH_KEY`    | Release          | yes          | SSH private key for signed commits/tags                             |
| secret | `ELECTROBUN_DEVELOPER_ID`    | Publish          | optional     | Apple Developer ID cert CN — gates the signing path                 |
| secret | `MAC_CERTIFICATE_BASE64`     | Publish          | conditional¹ | `.p12` cert, base64-encoded                                         |
| secret | `MAC_CERT_PASSWORD`          | Publish          | conditional¹ | `.p12` export password                                              |
| secret | `ELECTROBUN_APPLEID`         | Publish          | conditional¹ | Apple ID email                                                      |
| secret | `ELECTROBUN_APPLEIDPASS`     | Publish          | conditional¹ | App-specific password from `appleid.apple.com`                      |
| secret | `ELECTROBUN_TEAMID`          | Publish          | conditional¹ | 10-char Team ID from `developer.apple.com`                          |
| var    | `RELEASE_SIGNING_SIGNER_PUB` | Release          | yes          | SSH public key (matches `RELEASE_SIGNING_SSH_KEY`)                  |
| var    | `RELEASE_GIT_USER_NAME`      | Release          | optional²    | Defaults to `github-actions[bot]`                                   |
| var    | `RELEASE_GIT_USER_EMAIL`     | Release          | optional²    | Defaults to `41898282+github-actions[bot]@users.noreply.github.com` |

¹ Required when `ELECTROBUN_DEVELOPER_ID` is set. Empty `ELECTROBUN_DEVELOPER_ID`
  → mac leg falls back to unsigned, all five Apple secrets ignored.

² Falls back to bot identity. Set if you want author attribution on release
  commits.

## WORKFLOW: review.yml

### Trigger

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
    branches: [main]
```

All jobs gated by `if: github.event.pull_request.draft == false`.

### Jobs

#### `lint` — `ubuntu-latest`

Runs the Phase-1 quality chain in a single grouped step with exit-code
aggregation. Order:

1. Biome (with GitHub annotations) — `bun run lint:biome:ci`
2. Knip — `bun run lint:knip:ci`
3. dependency-cruiser — `bun run lint:depcruise:ci`
4. JSCPD — `bun run lint:jscpd:ci`
5. ls-lint — `bun run lint:ls:ci`
6. ast-grep — `bun run lint:ast-grep:ci`
7. tombi (mise.toml) — `bun run lint:mise:ci`
8. TypeScript — `bun run typecheck`

Each step writes a per-tool report to `tmp/reports/linters/`. Aggregate exit
code fails the job. A markdown summary is written to `$GITHUB_STEP_SUMMARY`
and uploaded as artifact `report-linters` (7-day retention).

Permissions: `contents: read`, `checks: write`.

#### `test` — `ubuntu-latest`

1. `bun run test:ci` (JUnit + coverage).
2. `./.github/actions/junit-summary` → markdown.
3. Upload artifact `report-tests` (7-day retention) including coverage.
4. `mikepenz/action-junit-report@v5` to publish a check.

Permissions: `contents: read`, `checks: write`.

#### `build` — `ubuntu-latest`

1. Cache `~/.electrobun` (Electrobun framework download).
2. `bun run build` with `ELECTROBUN_DEVELOPER_ID=""` (forces unsigned).
3. Upload artifact `build-smoke-linux-x64` (3-day retention) for reviewer
   download.

Permissions: `contents: read`.

### Local mirror

`mise run ci:review`

## WORKFLOW: release.yml

### Trigger

```yaml
on:
  push:
    branches: [main]
```

### Required merge strategy

**Squash and merge only.** The workflow detects and rejects:

- "Create a merge commit" — via `Merge pull request|branch` regex on the head
  commit subject.
- "Rebase and merge" — via `git log --oneline before..after | wc -l > 1`.

Rationale: any non-squash merge produces multiple commits on `main` per PR,
generating multiple changelog entries (including work-in-progress noise) and
breaking SHA-based signing.

### Job: `release` — `ubuntu-latest`

Permissions: `contents: write`, `issues: write`, `pull-requests: write`,
`id-token: write`.

Steps in order:

1. **Checkout** with `fetch-depth: 0` (release-it needs full tag history).
2. **Validate squash-and-merge** strategy. Skip on initial push (zero-SHA
   `before`). Fail the run with `::error::` and remediation message on
   non-squash merges.
3. **Setup** via `./.github/actions/setup-bun-project` (mise mode).
4. **Start ssh-agent** — `webfactory/ssh-agent@v0.9.0` with
   `RELEASE_SIGNING_SSH_KEY`.
5. **Configure git signing + identity:**
   - `git config gpg.format ssh`
   - Write `RELEASE_SIGNING_SIGNER_PUB` (var, preferred) or fall back to
     `ssh-add -L | head -n 1` to `~/.ssh/release_signing_key.pub`.
   - `git config user.signingkey ~/.ssh/release_signing_key.pub`
   - `git config commit.gpgsign true`, `git config tag.gpgsign true`
   - Identity from `RELEASE_GIT_USER_NAME` / `RELEASE_GIT_USER_EMAIL`,
     fallback to bot identity.
6. **Verify signing works** — two-part self-test on a throwaway file:
   - Signed commit: `git commit -m "test: signing" -S` and assert `gpgsig`
     header in `git cat-file -p HEAD`.
   - Signed tag: `git tag -s "signing-test-tag-$$"` and assert
     `BEGIN PGP SIGNATURE` or `BEGIN SSH SIGNATURE` block in tag object.
   - Cleanup unconditionally via trap.
7. **Pull latest changes** — `git pull --rebase origin main` (defensive
   against push races).
8. **Run release-it** — `bun run release:ci` with `GH_TOKEN` env var.
9. **Verify draft release was created** — poll `gh release list --limit 1`
   for `isDraft: true` 10 times × 5s. Exit 0 either way; "no draft" means
   "no releasable commits in this push," which is normal for chore/docs
   pushes.

### `release-it` configuration

Inlined in `package.json` under the `release-it` key:

- `git.commitMessage`: `chore(release): v${version}` (gitlint-compatible).
- `git.tagName`: `v${version}`.
- `git.requireBranch`: `main`.
- `git.requireCleanWorkingDir`: `true`.
- `git.requireCommits`: `true`.
- `github.release`: `true`.
- `github.draft`: `true` (publish workflow flips to public).
- `github.releaseName`: `v${version}`.
- `github.tokenRef`: `GH_TOKEN`.
- `github.autoGenerate`: `false` (notes come from CHANGELOG).
- `npm.publish`: `false`.
- `hooks.before:init`: `["bun run lint", "bun run test"]` (defense-in-depth
  re-run of PR checks).
- `hooks.after:bump`: `bun run -- typecheck`.
- `plugins["@release-it/conventional-changelog"]`:
  - `preset: { name: "conventionalcommits" }`
  - `infile: "CHANGELOG.md"`
  - `header`: standard "Changelog" header.

### `release:ci` script

```
"release:ci": "bunx release-it --ci"
```

### Local mirror

```sh
mise run ci:release:check-squash
mise run ci:release:check-signing
mise run ci:release:dry-run
mise run ci:release:notes
```

## WORKFLOW: publish.yml

### Trigger

```yaml
on:
  workflow_run:
    workflows: [Release]
    types: [completed]
  workflow_dispatch:
    inputs:
      tag:
        description: 'Tag to publish (e.g. v1.2.3)'
        required: true
        type: string
```

### Job DAG

```
resolve_tag
    │
    ├──► binaries (matrix: linux-x64, linux-arm64, darwin-arm64)
    │       │
    │       └──► checksums
    │              │
    │              └──► attach_release
    │                       │
    │                       └──► publish_release
```

### Job: `resolve_tag` — `ubuntu-latest`

Output: `tag` (the v*-prefixed release tag).

Steps:

1. If triggered by `workflow_run` and the upstream Release workflow's
   conclusion is not `success`, exit 1 with a clear message.
2. Resolve `TAG` from `inputs.tag` (workflow_dispatch) or from the latest
   draft release via
   `gh release list --limit 1 --json tagName,isDraft --jq 'if .[0].isDraft then .[0].tagName else "" end'`.
3. Empty `TAG` → exit 1 with "Could not resolve a release tag."

Permissions: `contents: read`. Uses `secrets.GH_TOKEN`.

### Job: `binaries` (matrix) — per-runner

Strategy: `fail-fast: false`.

| `target`       | `runner`           | `electrobun_platform` | `artifact_ext` |
| -------------- | ------------------ | --------------------- | -------------- |
| `linux-x64`    | `ubuntu-latest`    | `linux`               | `tar.gz`       |
| `linux-arm64`  | `ubuntu-24.04-arm` | `linux`               | `tar.gz`       |
| `darwin-arm64` | `macos-latest`     | `mac`                 | `dmg`          |

Permissions per leg: `id-token: write`, `contents: read`,
`attestations: write`.

Steps in order:

1. **Checkout the release tag** — `actions/checkout@v4` with
   `ref: ${{ needs.resolve_tag.outputs.tag }}`, `fetch-depth: 0`.
2. **Setup** via `./.github/actions/setup-bun-project`.
3. **Cache** `~/.electrobun` keyed on `runner.os`, `runner.arch`,
   `package.json` hash.
4. **macOS signing path only** (`if: matrix.target == 'darwin-arm64' && env.ELECTROBUN_DEVELOPER_ID != ''`):
   - Decode `MAC_CERTIFICATE_BASE64` to `$RUNNER_TEMP/cert.p12`.
   - Create ephemeral keychain at `$RUNNER_TEMP/build.keychain-db` with a
     random password, 6h timeout, set as default user keychain.
   - `security import` the cert with `MAC_CERT_PASSWORD`.
   - `security set-key-partition-list -S apple-tool:,apple:,codesign:` to
     allow `codesign` to use the cert non-interactively.
   - `rm` the `.p12` file.
5. **Build** — `bun run build:prod` with `ELECTROBUN_*` env vars wired from
   secrets. Electrobun's `electrobun.config.ts` reads these and decides
   whether to sign + notarize + staple internally.
6. **Package** via `./.github/actions/package-electrobun`:
   - Linux: `tar czf "app-${VER}-${TARGET}.tar.gz" -C <electrobun-output> .`
   - Mac (signed): find `*.dmg` in Electrobun output, rename to
     `app-${VER}-darwin-arm64.dmg`.
   - Mac (unsigned, when `ELECTROBUN_DEVELOPER_ID` empty): same but rename
     to `app-${VER}-darwin-arm64-unsigned.dmg`.
7. **Attest build provenance** — `actions/attest-build-provenance@v2` with
   `subject-path: <archive>`.
8. **Upload artifact** `binary-${{ matrix.target }}` (1-day retention).

### Job: `checksums` — `ubuntu-latest`

Needs `binaries`. Permissions: `contents: read`, `id-token: write`,
`attestations: write`.

Steps:

1. Download all `binary-*` artifacts to `assets/`, `merge-multiple: true`.
2. `cd assets && sha256sum *.tar.gz *.dmg 2>/dev/null > checksums.txt`.
3. `actions/attest-build-provenance@v2` with `subject-path: assets/checksums.txt`.
4. Upload artifact `checksums` (1-day retention).

The `2>/dev/null` is defensive: if a leg failed and produced no `.dmg` /
`.tar.gz`, the resulting `checksums.txt` only includes what the matrix
actually produced.

### Job: `attach_release` — `ubuntu-latest`

Needs `[checksums, resolve_tag]`. Permissions: `contents: write`. Single-writer
pattern: only this job touches the GitHub Release surface.

Steps:

1. Download all artifacts to `release-assets/`, `merge-multiple: true`.
2. `softprops/action-gh-release@v2` upload `*.tar.gz`, `*.dmg`,
   `checksums.txt` to the existing draft release at
   `${{ env.RELEASE_TAG }}` (idempotent — overwrites by default).
3. Verify each asset's attestation:
   ```bash
   gh release download "$RELEASE_TAG" --pattern '*.tar.gz' --pattern '*.dmg' --pattern 'checksums.txt' --dir /tmp/verify-assets
   for f in /tmp/verify-assets/*; do
     gh attestation verify "$f" --repo "$GITHUB_REPOSITORY"
   done
   ```

### Job: `publish_release` — `ubuntu-latest`

Needs `[attach_release, resolve_tag]`. Permissions: `contents: write`.

Steps:

1. **Re-verify all release assets** — download release, run
   `gh attestation verify` over every asset. Catches tampering between
   `attach_release` completion and now.
2. **Build install notes** — heredoc to `/tmp/install.md` with:
   - macOS install instructions (drag to Applications + `xattr -d` for
     unsigned builds).
   - Linux install instructions (extract `.tar.gz`, `chmod +x`, optional
     `~/.local/bin/`).
   - Verify section (`sha256sum -c checksums.txt` + `gh attestation verify`).
   - Prepend existing draft body.
3. **Publish the draft:**
   ```bash
   gh release edit "$RELEASE_TAG" --draft=false --latest --notes-file /tmp/release-notes.md
   ```

### macOS signing fallback

| `ELECTROBUN_DEVELOPER_ID` | Mac leg behavior                                                                 | Artifact filename                     |
| ------------------------- | -------------------------------------------------------------------------------- | ------------------------------------- |
| empty / unset             | Build unsigned `.app`, Electrobun produces unsigned `.dmg`, skip notarize/staple | `app-<ver>-darwin-arm64-unsigned.dmg` |
| non-empty                 | Full sign + notarize + staple via Electrobun's built-in pipeline                 | `app-<ver>-darwin-arm64.dmg`          |

The four conditional Apple secrets (`MAC_CERTIFICATE_BASE64`, `MAC_CERT_PASSWORD`,
`ELECTROBUN_APPLEID`, `ELECTROBUN_APPLEIDPASS`, `ELECTROBUN_TEAMID`) are
required only when `ELECTROBUN_DEVELOPER_ID` is set. The CI mac leg's keychain
import step is gated on `env.ELECTROBUN_DEVELOPER_ID != ''`.

### Local mirror

`mise run ci:publish --version=<ver>`

## ELECTROBUN CONFIG (electrobun.config.ts)

The existing `electrobun.config.ts` (committed in Phase 0) is extended with
an env-driven signing block. The roadmap's example shape (`mac.identity`,
`mac.notarize: { teamId, appleId, ... }`, `mac.entitlements: 'entitlements.mac.plist'`)
does **not** match the actual `ElectrobunConfig` schema in
`node_modules/electrobun/dist/api/bun/ElectrobunConfig.ts`. The actual API:

- `build.mac.codesign: boolean` — toggle (default false).
- `build.mac.notarize: boolean` — toggle (default false; requires codesign).
- `build.mac.createDmg: boolean` — default true. Electrobun creates the DMG
  itself.
- `build.mac.entitlements: Record<string, boolean | string | string[]>` —
  inline entitlements object. Electrobun writes the plist.
- Env vars Electrobun reads at build time:
  - `ELECTROBUN_DEVELOPER_ID` (cert CN; required when `codesign: true`).
  - `ELECTROBUN_APPLEID` / `ELECTROBUN_APPLEIDPASS` / `ELECTROBUN_TEAMID`
    (Apple ID credentials path for notarize).
- Signing only runs when `OS === "macos" && targetOS === "macos"` (the CLI
  enforces this; aligns with our `macos-latest` runner choice).

### Final shape

```ts
import type { ElectrobunConfig } from 'electrobun'

const appIconset = 'assets/icons/app-logo.iconset'

const developerId = process.env.ELECTROBUN_DEVELOPER_ID ?? ''
const appleId     = process.env.ELECTROBUN_APPLEID ?? ''
const appleIdPass = process.env.ELECTROBUN_APPLEIDPASS ?? ''
const appleTeamId = process.env.ELECTROBUN_TEAMID ?? ''

const canCodesign = developerId.length > 0
const canNotarize = canCodesign
  && appleId.length > 0
  && appleIdPass.length > 0
  && appleTeamId.length > 0

export default {
  app: { name: 'app', identifier: 'sh.blackboard.app', version: '0.1.0' },
  build: {
    bun:   { entrypoint: 'src/shell/main/index.ts' },
    views: { shell: { entrypoint: 'src/shell/renderer/index.ts' } },
    copy:  {
      'src/shell/renderer/index.html': 'views/shell/index.html',
      'assets/images':                 'views/shell/assets/images'
    },
    mac: {
      icons:     appIconset,
      bundleCEF: false,
      codesign:  canCodesign,
      notarize:  canNotarize,
      createDmg: true,
      entitlements: {
        'com.apple.security.cs.allow-jit':                        true,
        'com.apple.security.cs.allow-unsigned-executable-memory': true,
        'com.apple.security.cs.disable-library-validation':       true,
        'com.apple.security.network.client':                      true
      }
    },
    linux: { icon: `${appIconset}/icon_256x256.png`, bundleCEF: false }
  }
} satisfies ElectrobunConfig
```

## COMPOSITE ACTIONS

### `.github/actions/setup-bun-project/action.yml`

Inputs:
- `setup_mode`: `bun` | `mise` (default `bun`; we pass `mise` from each
  workflow so ast-grep is available).
- `bun_version`: default `latest`.
- `mise_version`: default pinned (e.g. `2026.3.9`).

Steps:
1. If `setup_mode == bun`: `oven-sh/setup-bun@v2`.
2. If `setup_mode == mise`: `jdx/mise-action@v4` with `install: true, cache: true`.
3. `actions/cache@v4` for `~/.bun/install/cache` keyed on `bun.lock` hash.
4. `bun install --frozen-lockfile`.

### `.github/actions/junit-summary/action.yml`

Inputs: `xml_path`, `output_path`, `title`.

Pure-bash extractor: greps `tests=`, `failures=`, `skipped=`, `time=` from
the JUnit `<testsuites>` root, computes `passed = tests - failures - skipped`,
writes a single-row markdown table to `output_path` with the title heading.

### `.github/actions/package-electrobun/action.yml`

Inputs: `target`, `platform`, `version`, `dist_dir`, `apple_identity`.

Output: `archive` (the produced filename).

Behavior:
- `platform == linux`: `tar czf "app-${version}-${target}.tar.gz" -C "${dist_dir}" .`
- `platform == mac`:
  - Find Electrobun's output `*.dmg` under `${dist_dir}` (max-depth 3).
  - If `apple_identity` empty → suffix `-unsigned`.
  - `mv` to final filename `app-${version}-${target}${suffix}.dmg`.
  - The composite does **not** call `codesign`, `hdiutil`, `xcrun notarytool`,
    or `xcrun stapler` — Electrobun has already done all of those internally
    (or skipped them, in the unsigned path).

## MISE.TOML — CI MIRROR TASKS

All Phase-2 tasks live under the `ci:*` namespace. The umbrella tasks
(`ci:review`, `ci:publish`) depend on the existing `prepare` task (which
runs `bun install`). Subtasks do not depend on `prepare` so iterative runs
stay fast.

| Task                       | Depends   | Description                                                                                         |
| -------------------------- | --------- | --------------------------------------------------------------------------------------------------- |
| `ci:review`                | `prepare` | Mirror review.yml end-to-end (lint + test + build)                                                  |
| `ci:review:lint`           | —         | `bun run lint` (full Phase-1 chain)                                                                 |
| `ci:review:test`           | —         | `bun run test:ci` (with coverage)                                                                   |
| `ci:review:build`          | —         | `bun run build` with `ELECTROBUN_DEVELOPER_ID=""` (forced unsigned)                                 |
| `ci:release:check-squash`  | —         | Validate HEAD is a single squash commit                                                             |
| `ci:release:check-signing` | —         | Signed-commit + signed-tag self-test on a throwaway branch                                          |
| `ci:release:dry-run`       | —         | `bunx release-it --dry-run --ci`                                                                    |
| `ci:release:notes`         | —         | Preview only the next CHANGELOG entry                                                               |
| `ci:publish`               | `prepare` | Mirror publish.yml end-to-end (build + package + checksum)                                          |
| `ci:publish:build`         | —         | `bun run build:prod` for the local platform                                                         |
| `ci:publish:package`       | —         | Package `dist/` as `.tar.gz` (linux) or rename `.dmg` (mac); takes `--target` and `--version` flags |
| `ci:publish:checksum`      | —         | `sha256sum *.tar.gz *.dmg > checksums.txt`                                                          |

Apple cert keychain import, `gh release` calls, and `gh attestation verify`
are intentionally not mirrored — they require runtime state that doesn't
exist locally (CI-ephemeral keychain, GitHub OIDC token, repo write).
